# Data model
- Existing media unchanged; new segmented video filename=UUID.mp4|webm.parts-v1-PARTBYTES-SIZE; strict UUIDv4, safe integer sizes, size<=200MiB, 1<=partBytes<=45M, count2–21. New production partBytes10M. No object at descriptor key. Derived physical UUIDs from SHA256(domain/root/size/partBytes/index), each <=50M. size/storedBytes exact original size.
- Journal existing meta key video-upload:UUID; value={filename,owner,createdAt}, validated descriptor.root matches key, ownerUUID, server ISOtimestamp. Reserved bytes from descriptor, not client. New/uncommitted→parts persisted→media atomic insert→journal removed. Failure→parts cleanup→journal removed; failed cleanup retains reservation. Confirmed media excludes reservation. Startup old>=1h without confirmed media can clean only exact derived keys; with media never removes objects.
- Library.storage additive optional maxVideoFile,available,reserved; used/limit/maxFile remain compatible. available=max(0,limit-used); used includes confirmed storedBytes and known unconfirmed reservations. Legacy Firebase fallback remains maxFile per type.
